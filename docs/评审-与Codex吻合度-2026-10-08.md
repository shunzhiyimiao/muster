# Muster 与 Codex 吻合度评审(2026-10-08)

> 依据:对照 `../muster-codex`(openai/codex 受控 fork,基点 2026-07-29)仓库内的文档与源码,与本仓 143 个提交的实际交付逐项核对。可分享版本见 claude.ai 的评审页面。

## 总判断

**吻合度中低,名实不符。** 规划(原名 Constellation Codex)设想受控 fork 承担运行时;实际执行器是自建 muster-runner,Codex 只被借了三样:Responses 线协议(经 muster-gateway)、会话分叉语义(照抄 thread fork,并补上哈希链)、SKILL.md 文件格式。"teams 版 codex"只在 CLAUDE.md 首行,规划反而把"复刻 Teams 功能"列为非目标。Codex 上游同期已有并行 sub-agent、goals/token 预算、远程执行环境、review 模式、hooks、托管配置与 requirements.toml。

## 逐维度对照

| 维度 | Codex | Muster | 结论 |
|---|---|---|---|
| 定位 | 个人编码 Agent + OpenAI 模型 + 云端任务 | 主权与治理:密级路由、哈希链、审批、本地部署 | 互补,技术上分道 |
| 运行时 | app-server 是 GUI/IDE 正式接口 | 自建 runner,未接 app-server | 未复用 |
| 技能 | `.agents/skills`、`~/.agents/skills`、`/etc/codex/skills` | 仓库级同目录同格式;个人级 `~/.muster/skills` | 文件级互通,个人级不共享 |
| AGENTS.md | 核心指令机制,逐级拼接 | 完全不读 | 缺口 |
| 工作流 | 无对应物 | WORKFLOW.md 自创 | 原创 |
| 网关 | 只讲 Responses | 对外 Responses 对内 chat,哑管道 | 协议兼容,流量绕开治理 |
| 审批与沙箱 | 四档审批 + Seatbelt/bwrap + 网络策略代理 | worktree 隔离 + 合入审批;run_command 出网无封堵 | 各强一半 |
| 多 Agent | 并行 sub-agent、orchestrator、goals、远程环境 | 串行委派一层;工牌即审计主体 | 可追溯性独有 |
| 治理 | rollout 不防篡改;OTEL 是遥测 | 密级路由、append-only 哈希链、审批、隔离 | 护城河,覆盖面不足 |
| 开发者工作流 | exec/SDK、IDE、MCP、hooks、plugins、review、记忆 | 仅工作流终端触发 | 缺口 |

## 守住 / 补上 / 收住

- **守住**:密级只升不降;append-only 哈希链;合入必经人审批、不提供 push/PR;工牌即 actor;每 run 独立 worktree。
- **补上**:P0 闸门(本地模型零公网)未过;不读 AGENTS.md;个人技能目录不一致;run_command 出网与网关流量无治理;无 MCP/CLI/SDK/IDE/review 准则。
- **收住**:LiveKit 会议违反非目标第一条;一排占位功能;技能/工作流/编制规划外(技能与 Codex 对齐,保留);P0 未过就开工 P2/P3 与会议。

## 受控 fork 的真实状态

相对上游仅改 FORK.md 与 NOTICE 共 34 行,零代码;基点停在 2026-07-29 从未 rebase。规划交给它的三件事(离线模式、本地 Provider 策略、企业审计 Hook)上游现在都能靠配置做到(oss provider、网络代理全禁、hooks、requirements.toml、OTEL)。结论:既没用上也没必要。

## 决定:走路 B(自主运行时,明说借鉴)

保留 muster-runner 与治理层;定位改为"AI 原生团队协作系统,兼容 Codex 的技能与接口约定";有选择地吸收 Codex 资产。未选路 A 的原因:要推翻 runner 全部积累,且审计链要信任 Codex 事件,证据属性变弱。

下一步按序:

1. 补 P0 闸门:装 Ollama,A7 在本地模型上跑通,零公网演习出报告。
2. 改口号:CLAUDE.md、README 首行与对外描述统一;清理"点将"等内部术语。
3. 读 AGENTS.md:项目根到当前目录逐级拼接,进系统提示词。
4. 技能个人级兼读 `~/.agents/skills`。
5. 复用 codex-rs 的沙箱与网络代理(Apache-2.0)补 run_command 出网缺口。
6. 网关二选一:接入密级路由与审计,或明确只给本机开发用。
7. 给 fork 一个结局:删除或固定上游版本做参考。
8. 冻结占位功能;会议线写进规划或停。
