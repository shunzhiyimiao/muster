# 配置助手(计划,2026-11-08 用户提出)

> 一句话:让组织所有者**不碰命令行**就能把一个新部署用起来——配好 Agent 的模型通道,给成员开好账号。
> 现状是这两件事分别要在服务器上跑 `muster-admin provider-add` / `account-add`,或者让成员自己注册再逐个批准。

## 要做什么

1. **Agent 的 API(模型通道)配置**
   - 列出 / 新增 / 修改 provider 目录(id、base_url、model、locality、api_key_env、超时、启停、默认位),对应服务端 `/providers`;
   - 按厂商给预设(Kimi、DashScope、DeepSeek、本地 Ollama),填 model 和密钥变量名就行,base_url 与 locality 由预设带出;
   - **密钥不进服务端**(边界六):助手只写**环境变量名**到目录;真正的密钥要落在跑 Agent 的节点上
     (生产是服务器 `deploy/.env` → node 容器)。助手要把这一步说清楚,并能**探活**:让节点拿当前环境里的密钥
     打一次 `/models`,报"通 / 401 / 变量没设",别让人配完才在会上发现没声音;
   - 探活不等于把密钥上传:节点自己测,结果只回一个状态。
2. **给成员注册账号**
   - 批量开号:一次填多行「账号 id、显示名、邮箱、部门」,生成初始口令或直接签发**重置链接**
     (已有 `/accounts/:aid/reset-link`,30 分钟一次性),把链接发给本人自己设口令——比发初始口令干净;
   - 顺手授权:选团队 / 频道 / 角色(member / approver…),对应 `/roles` 与 channel_member;
   - 待批准队列就在旁边(已有「服务端账号」卡),一处管完。

## 放在哪

- 桌面壳,组织所有者 / 管理员可见(`whoami.can.manage_members` / `change_policy`),入口建议在「团队 › 编制」页顶部,
  或首次连上服务端且目录为空、成员只有 owner 时**主动弹出**(首跑向导);
- 不做网页后台(架构文档 §5.5 的取舍不变):助手走的仍是 muster-admin 同一套接口,CLI 照旧能做一切。

## 已有的积木

- 服务端:`/providers`(ChangePolicy)、`/accounts` `/roles` `/accounts/:aid/approve` `/accounts/:aid/reset-link`、`/org/registration`;
- 桌面壳:`remoteAccounts / remoteAccountApprove / remoteResetLink / remoteRegistrationSet` 已接;provider 目录读写还没接到桌面壳(`remoteCatalog` 只读)。

## 待定(动手前问用户)

- 批量开号用「初始口令」还是「重置链接」?(建议链接)
- 探活由谁做:节点(需要加一个 `/nodes/:id/probe` 的设定值让节点去测并回报)还是桌面壳本机?
  桌面壳本机测只能证明"这台 Mac 上的密钥通",证明不了服务器上的节点通。
- 预设厂商清单与默认 model。
