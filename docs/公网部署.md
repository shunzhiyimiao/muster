# 公网部署(自有域名)

## 先说清楚 HTTPS 不是可选项

不是"更安全一点",而是**能不能用**:

浏览器只在**安全上下文**里给 `getUserMedia`。`http://` 加域名不是安全上下文,
所以**麦克风根本打不开**——而报错只会说权限被拒,看不出是协议的问题。
局域网测试一直没撞见这堵墙,是因为 `http://localhost` 是浏览器特批的例外。

连带的:HTTPS 页面不许开 `ws://` 连接(混合内容)。所以 LiveKit 的信令
也必须是 `wss://`。这就是下面要两个主机名的原因。

## 你需要准备的

| 项 | 说明 |
|---|---|
| 一台有公网 IP 的服务器 | 2 核 4G 起。whisper 转写吃 CPU,人多要加 |
| 域名的 DNS 控制权 | 要加两条 A 记录 |
| 开放的端口 | 80、443/tcp;7882、3478/udp |

DNS 两条都指向服务器 IP:

```
muster.example.com        A    <服务器 IP>
livekit.muster.example.com A   <服务器 IP>
```

`80` 是 Let's Encrypt 签发证书要走的校验;签完也别关,证书续期还要用。

## 部署

```bash
git clone https://github.com/<你>/muster.git && cd muster
cp deploy/prod.env.example deploy/.env
$EDITOR deploy/.env          # 三处密钥全部换掉,域名填自己的
docker compose --env-file deploy/.env -f deploy/docker-compose.prod.yml up -d --build
```

第一次要几分钟(编 Rust)。起来之后建组织所有者:

```bash
docker compose --env-file deploy/.env -f deploy/docker-compose.prod.yml \
  exec muster-server muster-bootstrap owner '<你的口令>' 老板
```

建团队和频道用同一个镜像里的 `muster-admin`:

```bash
C="docker compose --env-file deploy/.env -f deploy/docker-compose.prod.yml exec muster-server"
$C muster-admin login owner '<你的口令>'
$C muster-admin team-add platform 平台组
$C muster-admin channel-add platform-main platform 主频道 internal
$C muster-admin account-add alice '<口令>' Alice human
$C muster-admin grant alice member org
```

然后浏览器开 `https://muster.example.com`。

## 服务端会拒绝启动的几种情况

配置检查在连数据库之前就做完了,而且**一次把话说全**——在一台新服务器上
一次只发现一个问题、改完再重启,太费时间。

- `MUSTER_JWT_SECRET` 不到 32 字符
- 对外监听却没设 `MUSTER_ALLOWED_ORIGINS`

第二条是这次上公网新加的闸。放开 CORS 在局域网里只是方便,暴露到公网上,
它把每一个 XSS、每一个恶意页面都变成对本服务的通道——**而这种事故没有任何
症状,一切正常工作,直到出事**。所以宁可让它起不来。

## 与开发部署的区别不是参数,是威胁模型

`deploy/docker-compose.yml`(开发)假设"能碰到它的人本来就在楼里"。
公网那份里几处刻意的收紧:

- **数据库不映射端口。** 开发那份映射 5433 是为了本机 psql 方便;
  公网上映射出去等于把 Postgres 挂在互联网上,而弱口令扫描器最爱这个。
  要连库用 `docker compose exec postgres psql -U muster`。
- **whisper 不映射端口。** 它是个无鉴权的转写接口,暴露出去谁都能白嫖算力。
- **登录限流。** `/auth/login` 是唯一免鉴权的写接口,公网上每天会被扫成千上万次。
  Argon2 让单次猜测很贵,但那是防拖库后离线爆破的;在线爆破面前,昂贵的哈希
  反而成了拒绝服务的把手。
- **密钥没有仓库里的默认值可用。** 开发那份的 `devsecret…` 是公开在仓库里的。

限流分两维,额度差很多:**账号 10 次/5 分钟,IP 60 次/5 分钟**。
IP 那一维必须宽——一整间办公室共用一个出口 IP,按账号的额度去限,
几个同事先后输错密码就把全公司锁在外面。

## 会议连不上时的排查顺序

按这个顺序查,不要跳:

1. **能不能开麦。** 打不开先看地址栏是不是 `https://`。不是的话到此为止,
   别去查 LiveKit。
2. **进不进得去房间。** 报 `signal connection` / `Failed to fetch` 是**信令**
   ——检查 `livekit.<域名>` 的 DNS 和证书,`curl -I https://livekit.<域名>`。
3. **报 `could not establish pc connection` 是媒体**,信令已经通了。
   检查 UDP 7882 有没有被防火墙/安全组挡掉。云主机的安全组是最常见的一处。

信令和媒体是两条路,**症状相似而原因完全不同**——之前在局域网上就因为
把信令的问题归咎于媒体配置,查错了方向。

## 已知缺口

**全 UDP 被封的网络进不来。** TURN 只开了 UDP 3478。要覆盖这种网络需要
TURN over TLS,而 443 已经被 Caddy 占着,得用四层转发才拼得起来。
这条没做,也没在配置里假装做了。

**服务端不做全局审计链。** 各节点各自留链,组织侧靠锚定——**锚定还没实现**。
也就是说服务端存的东西被改了,目前没有机制能发现。这条记在
`muster-server/src/lib.rs` 的诚实边界里,上公网并没有改变它,
但公网让它更值得优先。

**限流是进程内存、单节点。** 重启即清零,多副本各限各的。

**没有备份。** `pgdata` 卷丢了就全没了。上生产前至少加一条
`pg_dump` 的定时任务。

## 客户端怎么连

**网页端**:浏览器开 `https://muster.example.com`,不用装任何东西。

**桌面壳**:侧栏填 `https://muster.example.com`。它的请求走 Tauri 的 Rust 侧,
不经浏览器 CORS,所以不必把它加进白名单。

**会议 Agent**:跑在服务器上(或任何能连到服务端的机器),环境变量指向
`https://muster.example.com`,`MUSTER_STT_URL` 指向 compose 网络里的
`http://whisper:8000/v1`。
