## 块 1 · 服务端两处安全 / 正确性欠账(约 3 小时)

**做什么**:SSE 一次性 ticket;消息 POST 幂等。两件都小,都是公网上线前的欠账。

**给 Claude Code 的 prompt**

```
先读 CLAUDE.md、muster-server/src/lib.rs 的「诚实边界」、docs/服务端架构.md。只做下面两件,别顺手重构。

1) SSE 一次性 ticket。现在 /events?token=<JWT>,令牌会进日志和浏览器历史。
   - 新增 POST /events/ticket(要求正常 Bearer 鉴权),返回 {ticket},ticket 为 32 字节随机数,
     服务端只存其 SHA-256、绑定账号、TTL 60 秒、只能用一次。
   - GET /events 改为接受 ?ticket=;用过即作废;过期或重放返回 401。
   - 过渡期:?token= 仍可用但打一条 warn 日志,网页端与桌面壳全部改用 ticket;
     在诚实边界里记「?token= 兼容路径:负责人 Li,复查条件:桌面壳下一版发布后删除」。
   - 测试:ticket 只能用一次;过期拒绝;别人的 ticket 不能订到别人的流。

2) 消息 POST 幂等。
   - POST /channels/:cid/messages 接受可选头 Idempotency-Key(≤128 字符)。
   - 新迁移 0002:message 表加 idempotency_key 列,(author, idempotency_key) 唯一(为空不约束)。
   - 同 author 同 key 再来一次:返回第一次的结果(同一 id、同一 stream_seq),不落第二条、不再广播。
   - 网页端与桌面壳发消息时生成 UUID 作 key,重试沿用同一个。
   - 测试:并发两次同 key 只落一条;不同作者同 key 互不影响。

两件都进服务端审计链的现有事件即可,不新增事件类型。改完更新 lib.rs 诚实边界(划掉幂等那条,改写令牌那条),
cargo test 全绿,meetings_e2e 全绿。一个 commit 一件事。
```

**验收**:两个新测试组全绿;网页端与桌面壳实测能连上推送、发消息不重复。

## 块 2 · 组织节点 + 值班 Agent(约 6 小时,最大的一块)

**做什么**:节点设计第 1 步。会议 daemon 从「拿 A-007 口令登录」改成「以节点身份登录,托管 `org.duty_badge`」。
顺带熔断与带进度的心跳。

**给 Claude Code 的 prompt**

```
先读 docs/节点与工牌-公用私有值班.md 全文,只实现其中「实施顺序 · 1」,不做派发单、不做私有 Agent。
再读 muster-meeting-agent/examples/daemon.rs 的对账循环、muster-server/src/meeting.rs 的 agent_wanted。

服务端(迁移 0003):
- node(id, name, owner_account NULL, pubkey BYTEA, capabilities JSONB, version, last_seen_ms,
  last_progress_ms, last_progress_kind, created_ms)。owner_account 为 NULL 即组织节点。
- 账号表的 agent 类账号(工牌)加 node_id;组织设置加 duty_badge(必须是 agent 类、已分配到某节点)。
- 入网(设备码):POST /nodes/enroll {name, pubkey, capabilities} → {node_id, user_code, poll_token};
  管理员在网页 POST /nodes/enroll/:user_code/approve;节点轮询 GET /nodes/enroll/poll 直到批准。
  公钥是节点本地生成的 ed25519,服务端只存公钥。
- 会话:POST /nodes/:id/challenge → nonce;POST /nodes/:id/session {sig} 验签后签发短期 JWT
  (claims 标明 node_id,不是任何人的账号)。复用现有 JWT 设施。
- GET /nodes/:id/desired:该节点托管哪些工牌、其中值班工牌该进哪些会(即现在 agent_wanted 的结果,
  但只给 duty_badge 所在的节点)。
- POST /nodes/:id/heartbeat {version, capabilities, progress:{kind, at_ms}}:更新 last_seen / last_progress。
  超过 90 秒无心跳 ⇒ 该节点上的工牌在 /whoami 等处显示不可用。
- 节点会话只能代表它托管的工牌行事:以值班工牌身份发纪要、发回顾、提行动项;用别的工牌身份一律 403。
- 所有入网批准、工牌分配、duty_badge 变更进服务端审计链(badge.update 已有就复用)。

会议 daemon(改成节点):
- 首次运行无密钥 ⇒ 生成 ed25519 存 $MUSTER_NODE_HOME/node.key(0600),走入网,打印 user_code 等管理员批准。
- 之后用 challenge/session 拿 JWT,订 SSE、按 desired 对账。保留 MUSTER_ACCOUNT/MUSTER_PASSWORD 作为
  过渡路径(打 warn),在诚实边界记「口令登录路径:负责人 Li,复查条件:muster.top 切到节点身份后删除」。
- 熔断:同一会议连续 3 次以同一错误类别失败 ⇒ 停止认领该会议,心跳里上报 {breaker: meeting_id, error_kind},
  服务端记一条事件;人点「重试」(POST /meetings/:mid/agent 再设一次)才解除。已有的退避重试保留。
- 心跳 progress:最近一次成功回传转写 / 纪要的时间。

部署:
- docker-compose.prod.yml 的 agent 服务改名 node,环境变量换成 MUSTER_NODE_HOME(挂一个命名卷存密钥)。
- muster-admin 加 nodes / node-approve <user_code> / badge-assign <badge> <node> / duty-set <badge>。
- deploy/to-server.sh:起服务后打印入网码,用 muster-admin 自动批准本机节点、把值班工牌分配过去、设 duty。

测试:入网未批准不能拿会话;节点 A 的会话不能以节点 B 托管的工牌发言;非 duty 工牌所在节点拿不到会议;
熔断三次后不再认领、重试后恢复;心跳超时后工牌显示不可用。cargo test、meetings_e2e 全绿。
改完更新 docs/服务端架构.md 的部署拓扑图(Meeting Agent 那一格改成「组织节点」),一个 commit 一个小步。
```

**验收**:本地 `./deploy/dev-up.sh` 下:新节点入网 → 管理员批准 → 开会点「请 Agent」→ 值班 Agent 入会、
纪要出字;拔掉 whisper 让它连错三次 ⇒ 熔断上报;恢复后点重试能回来。**本地全过才上 muster.top。**

## 风险与回滚

| 风险 | 预案 |
|---|---|
| 块 2 做到一半时间用完 | 停在块 1 完成的提交上发布;块 2 的分支不合入。daemon 保留口令过渡路径正是为此 |
| 迁移出错 | 每个迁移只加列 / 加表,不删不改已有列;线上部署前 `pg_dump` 一份 |

| Claude Code 越界顺手重构 | 每个 prompt 都限定「只做 X」;每块一个分支内多个小 commit,review diff 再合 |
