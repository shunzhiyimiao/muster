# 两人 + Agent 开会:测试计划

> 目标:验证**两个真人 + 一个 Agent** 同处一场会议。此前所有验证都只有一个人,
> 而"多人"恰恰是这个产品的立身之处——第二个人会暴露一批单人测不出的东西。

## 一、开测前:三个阻塞点(已修,但要确认)

单人测试全在 `localhost` 上做,而**第二台机器一个都用不了**:

| # | 问题 | 现象 | 已改成 |
|---|---|---|---|
| 1 | 服务端只听 `127.0.0.1` | 第二台连不上服务端 | `MUSTER_BIND=0.0.0.0:8787` |
| 2 | LiveKit 广播 `node_ip: 127.0.0.1` | 第二台报 **`could not establish pc connection`** | 注入局域网 IP |
| 3 | 会话文件路径写死 | 同机开两个壳,后登录的把先登录的挤掉 | `MUSTER_SESSION_FILE` 可覆盖 |

第 2 条尤其值得记:它和单机那次是**同一个症状、不同原因**。
排查手法一样——看 LiveKit 日志里 `[local][selected]` 那个候选地址,
不是对方能到的地址就是它。

```bash
docker logs deploy-livekit-1 2>&1 | grep -oE '\[local\]\[selected[^"]*' | tail -2
```

## 二、开场(约 10 分钟)

```bash
./deploy/dev-up.sh          # 打印局域网地址,建好 alice / bob / A-007
```

然后起常驻 Agent(**一次就够**,之后靠按钮请它进会):

```bash
source /tmp/muster-dev.env
export MUSTER_ACCOUNT=A-007 MUSTER_PASSWORD=agentpass123
export MUSTER_STT_MODEL=Systran/faster-whisper-base
export MUSTER_AGENT_ALIASES="小七,小齐,小气,小奇,小柒"
export MUSTER_STT_PROMPT="以下是简体中文的技术周会口语记录。常见词:小七、实时纪要、行动项、网关、幂等键、灰度发布、审批、密级。"
export MUSTER_PROVIDER_CONFIG=<你的 provider.toml>
cargo run -p muster-meeting-agent --features livekit --example daemon
```

两个人分别连 `http://<局域网IP>:8787`:alice / bob。
**同一台机器开两个壳**的话,第二个必须换会话文件:

```bash
MUSTER_SESSION_FILE=/tmp/muster-bob.json pnpm tauri dev
```

## 三、按顺序测(每步都能单独判定成败)

| # | 测什么 | 怎么做 | 对了应该看到 | 这一步在验什么 |
|---|---|---|---|---|
| 1 | 第二台能连服务端 | bob 登录 | 侧栏「已连接团队服务器」 | 阻塞点 1 |
| 2 | **消息互通** | alice 在频道发一条 | **bob 那边自动出现**(不刷新) | SSE 多客户端扇出 |
| 3 | 两人同处一会 | alice 发起会议,bob 从大厅进 | 双方「2 人在场」 | 阻塞点 2 |
| 4 | 请 Agent | 任一方点「请 Agent 来记录」 | 几秒后双方徽标变绿、变「3 人在场」 | 按钮 → daemon 认领 |
| 5 | **说话人归属** | 两人轮流各说一句 | 纪要里 alice / bob 各归各 | 每人一轨,不做声纹分离 |
| 6 | **同时说话** | 两人**故意同时**说 | 两条时间重叠的记录,各自内容独立 | 重叠说话不做分离(如实反映) |
| 7 | 叫 Agent | bob 说「小七,刚才 alice 说了什么」 | 它能引用 alice 的话作答 | 上下文跨说话人 |
| 8 | 转写负载 | 持续对话 2 分钟 | daemon 日志**不刷丢帧** | 2 人 = 2 倍转写压力 |
| 9 | 中途入会 | 重启 daemon | 日志「已补回 N 条既有纪要」 | 重连不失忆 |
| 10 | 行动项 | 一方说「我下周三之前把 X 做完」,停 daemon | 提出提案,状态 `proposed` | 提案 ≠ 任务 |
| 11 | **确认要人** | 用 A-007 的令牌去确认 | ⛔「必须由人确认」 | 授权边界 |

## 四、重点看这四件单人测不出的事

1. **说话人归属会不会串**(第 5/6 步)。两人一轨、互不干扰是设计前提,
   但只在合成音频上验过。
2. **同时说话**(第 6 步)。当前**不做重叠分离**,预期是两条时间重叠的记录。
   如果结果不是这样(比如一方的话进了另一方的记录),那是真 bug。
3. **转写跟不跟得上**(第 8 步)。base 单人是实时的 7 倍,两人理论上还有
   3.5 倍余量;但真人语速与噪声不同于合成音频,要看 daemon 有没有刷
   「转写跟不上采集,已丢帧」。**刷了就说明该上 GPU 或降到 tiny。**
4. **消息去重**(第 2 步)。前端按 `(ts, text)` 去重,两人**几乎同时发同样
   的话**理论上会被误判成重复。刻意试一次。

## 五、预计会撞到的(先想好,别现场慌)

| 可能现象 | 多半是 |
|---|---|
| bob 连不上服务端 | 防火墙,或 dev-up 没重跑(`MUSTER_BIND` 没生效) |
| 进会报 `pc connection` | LiveKit 候选还是 `127.0.0.1`——重跑 dev-up 让它注入局域网 IP |
| 两个壳互相挤掉登录 | 同机开两个没设 `MUSTER_SESSION_FILE` |
| Agent 不进会 | daemon 没跑,或它那边令牌过期(它会自己重登,看日志) |
| 转写把人名认错 | 别名表加词;这是 base 模型的已知上限 |

## 六、这次不测的

- 视频(只测语音;视频通不通与转写无关,而转写才是产品价值所在)
- 三人及以上
- 跨网段 / VPN(先在同一局域网内测通)
- 录制回放(还没做)

## 七、第二台真机怎么装(补充)

网络这层已经通了(防火墙关着,四个端口都听在 `*`),验收脚本会逐个探:

```bash
./deploy/check.sh                                      # 在第一台跑
MUSTER_SERVER=http://<第一台IP>:8787 ./deploy/check.sh  # 在第二台跑
```

第二台拿到桌面壳有两条路:

**A. 拷一个打好的 app(推荐)**

第一台执行 `cd apps/desktop && pnpm tauri build`,产物在
`apps/desktop/src-tauri/target/release/bundle/macos/*.app`(以及 `dmg/`)。
拷到第二台的「应用程序」即可。

未签名的 app 从网络传过去会被 Gatekeeper 拦(提示"已损坏"),两个办法:

```bash
xattr -dr com.apple.quarantine /Applications/muster-desktop.app   # 或
# 右键 → 打开 → 仍要打开
```

**B. 第二台也有仓库和工具链** —— `pnpm tauri dev`。首次要编 Rust 依赖,较慢,
但改代码后不用重新打包,适合边测边改。

### 同一台机器开两个壳(没有第二台时的退路)

```bash
MUSTER_SESSION_FILE=/tmp/muster-bob.json pnpm tauri dev
```

**必须换会话文件**,否则两个壳共用一份,后登录的把先登录的挤掉——
而界面上看不出来,只会觉得"怎么变成另一个人了"。

注意这条退路验不了两件事:局域网可达性,以及**两个麦克风**
(同机两个壳抢同一个输入设备,同时说话测不了)。
