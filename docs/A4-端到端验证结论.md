# A4 端到端验证结论

> 目的:在调切句质量(A3)之前,先证明**整条链真的通**。
> 结论:**通了**——但过程中撞出 6 个问题,全是只有真跑才会暴露的那种。

## 一、跑通的链路

```
推流端(owner 账号)→ LiveKit 房间
  → Agent(A-007 账号)订阅到音轨 speaker=owner
  → 能量闸切句 → 封 WAV
  → SpeechRouter 决策(本地落点)→ whisper 转写
  → POST /meetings/:id/transcript → PostgreSQL
```

落库结果:`owner → 各位好,我们开始今天的周会,第一项一题是网关的重试秘等键放在哪一层。`

**说话人归属正确**,而且是白拿的——LiveKit 每人一条轨,令牌 `sub` 就是 Muster 账号 id。

治理也在真机上验过:

| 场景 | 结果 |
|---|---|
| 演习 + 仅云端 STT | ⛔ fail-closed 拒绝,理由完整 |
| 演习 + 本地 STT | ✓ 放行,外发记 0 |
| Agent 账号查 `whoami` | `approve_merge: false`——Agent 永远不能自批 |

## 二、撞出来的 6 个问题

### 1. 冷启动数据不能用来下结论

第一次测出「6.2s 音频要 17.6s」,我差点据此判定"转写跟不上直播"。**那是模型在下载。**
热态重测:

| 模型 | 耗时(6.2s 音频) | 相对实时 |
|---|---|---|
| tiny | 0.5s | 快 12 倍 |
| **base** | **0.9s** | **快 7 倍** |

CPU 上 `base` 快 7 倍,直播会议绰绰有余。**教训:性能结论必须在热态测。**

### 2. 开发机上的本地 Postgres 会抢 5432

`role "muster" does not exist`——报错完全看不出根因:连上的是**另一个数据库**。
compose 改映射到 **5433**。原则:**不动用户已有的服务**。

### 3. LiveKit `--dev` 的密钥只有 6 字符

与 `muster-server` 要求 `LIVEKIT_API_SECRET ≥32` 冲突(房间准入全靠这把钥匙)。
不放宽校验,改为显式配 `LIVEKIT_KEYS`。**仓库里那把是公开的,内网部署必须换。**

### 4. macOS 上必须给链接器 `-ObjC`

症状:运行时崩 `+[NSString stringForAbslStringView:]: unrecognized selector`。
原因:WebRTC 静态库里有 ObjC **分类**,分类不产生符号引用,链接器默认把它整个剥掉。
`build.rs` 里加 `cargo:rustc-link-arg=-ObjC`。

**这类问题编译期毫无征兆**,只有真跑才会暴露——A4 存在的理由。

### 5. Agent 必须有独立账号

Agent 和推流端都用 owner 令牌 ⇒ LiveKit 报 `DuplicateIdentity`,把先进的踢掉。
这其实是设计在提醒:**Agent 是一个独立的参会主体**,`PrincipalKind::Agent` 本就是为它准备的。
建了 `A-007`,顺带验证了它 `approve_merge: false`。

### 6. 中文默认出繁体,技术术语转成同音别字

| | 无提示 | 带领域提示 | 原文 |
|---|---|---|---|
| 字形 | 繁体 | **简体** ✓ | 简体 |
| 周会 | 周慧 ✗ | **周会** ✓ | 周会 |
| 网关 | 網關 ✗ | **网关** ✓ | 网关 |
| 重试 | 重視 ✗ | **重试** ✓ | 重试 |
| 幂等键 | 密等鍵 ✗ | 秘等键 ✗ | 幂等键 |

领域提示是大改善,但**生僻术语仍拿不下**。后续:更大模型,或转写后接一层术语词典。
注意提示词**每次调用都原样发给后端 ⇒ 绝不能放机密内容**。

### 7. 忘了给 example 声明 required-features

新增的 `agent` / `speak_wav` 两个 example 依赖 livekit,而 `cargo test` **会编
examples**——于是 `cargo test --workspace` 当场因为找不到 livekit 而全挂,
把"默认构建不碰原生 WebRTC"这条前提废掉了。

讽刺的是,这条前提正是我在 A2 里花力气立的:核心与 SDK 分层、feature 默认关。
立了规矩,自己第一个踩。`Cargo.toml` 里补 `[[example]] required-features`。

**教训**:feature gate 要盖住**所有**编译目标,lib 之外还有 examples、benches、tests。

## 五、B1(被叫到时作答)的真机结论

链路:被叫到 → 取会议上下文 → 经 `muster_route`(**带会议密级**)问模型 →
回答写进同一份纪要。

```
owner → 各位好,我们开始今天的周会,第一项一题是网关的重试秘等键放在哪一层。
owner → 小七刚才说的蜜等键最后定在哪一层?
小七 → 会议记录里只提到 owner 提出了"幂等键放在哪一层"这个问题,
        但没有记录小七的回答或最终结论,所以我不知道最后定在了哪一层。
```

**答得诚实**:上下文里确实只有人提出问题、没有结论,它就说不知道,没有编。
系统提示里那句"不知道就说不知道,不要编造会上没说过的内容"起了作用。

### 又一个只有真跑才会暴露的问题:转写会把标点吃掉

原话是「小七**,**刚才说的…」,whisper 转成「小七刚才说的…」——逗号没了。
而我的词边界规则要求**别名后面跟标点或空白**,于是喊了它也听不见。

中文本来就不用空格分词,转写又常丢标点,**拿标点当词边界在语音场景里不成立**。
改成二选一:**别名在句首** 或 **别名后跟标点/空白**。这样:

| 输入 | 判定 |
|---|---|
| 小七刚才说的… | ✓ 句首 |
| 那么小七,你说呢 | ✓ 后跟逗号 |
| 这事儿小七七八八的还没定 | ✗ 既不在句首、后面也不是标点 |

教训与前面几条同类:**在文本上想当然成立的规则,到语音上未必成立**。
